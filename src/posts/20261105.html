Introducción

Durante más de veinte años, CSS solo supo mirar hacia abajo: un selector podía estilar a los hijos o descendientes de un elemento, pero nunca al elemento en función de lo que contenía. Con :has() eso cambia: ahora podemos decir “estila este contenedor si dentro tiene tal cosa”.

La petición era tan antigua que se convirtió en un clásico de los foros: “¿cómo selecciono el padre de un elemento?”. La respuesta siempre era la misma: no se puede, usa JavaScript o añade una clase extra al HTML.

El motivo era el rendimiento. Los navegadores evalúan los selectores de derecha a izquierda y aplican estilos mientras el documento se va construyendo. Un selector padre obliga a reevaluar ancestros cada vez que cambia un descendiente, algo que durante años se consideró demasiado costoso. Los motores han encontrado formas de acotar ese coste, y hoy :has() funciona en todos los navegadores modernos.

Qué es :has() y cómo se escribe

:has() es una pseudoclase relacional: selecciona un elemento si al menos uno de los selectores relativos que recibe encuentra coincidencia a partir de ese elemento. La sintaxis es A:has(B), y se lee “un A que tiene un B”.

El ejemplo canónico: estilar una tarjeta solo cuando contiene una imagen. 

	
<article class="card">
	<img src="portada.jpg" alt="">
	<h2>Con imagen</h2>
</article>

<article class="card">
	<h2>Sin imagen</h2>
</article>
	

	
/* Solo la primera tarjeta cumple la condición */
.card:has(img) {
	display: grid;
	grid-template-columns: 200px 1fr;
	gap: 1rem;
}

Fíjate en que el estilo se aplica a .card, no a la imagen. Eso es exactamente lo que antes era imposible.

Por defecto, el argumento busca entre todos los descendientes. Si quieres limitarlo a los hijos directos, usa el combinador > dentro del paréntesis: 

	
/* Solo si la imagen es hija directa de .card */
.card:has(> img) {
	padding: 0;
}

Más que un selector padre

Llamarlo “selector padre” se queda corto: :has() acepta cualquier selector relativo, así que también sirve para mirar hacia atrás entre hermanos, otra cosa que CSS no podía hacer.

Selector Selecciona
a:has(b) un a con algún descendiente b
a:has(> b) un a con un hijo directo b
a:has(+ b) un a seguido inmediatamente de un hermano b
a:has(~ b) un a con algún hermano posterior b

El combinador + permite, por ejemplo, ajustar el margen de un título solo cuando lo sigue un subtítulo: 

	
/* El h2 que va justo antes de un .subtitle */
h2:has(+ .subtitle) {
	margin-bottom: 0.25rem;
}

También admite una lista de selectores separada por comas. La condición se cumple si coincide cualquiera de ellos (lógica OR): 

	
/* Un aviso que contenga un icono o un botón */
.alert:has(svg, button) {
	padding-inline-start: 3rem;
}

Para exigir varias condiciones a la vez (lógica AND), encadena varios :has(): 

	
/* Una tarjeta con imagen Y con vídeo */
.card:has(img):has(video) {
	outline: 2px solid tomato;
}

Casos prácticos

Estos patrones sustituyen JavaScript o clases auxiliares que antes eran inevitables.

1. Formularios que reaccionan a su estado

Marca en rojo el grupo entero de un campo inválido, pero solo después de que el usuario haya escrito algo: 

	
.field:has(input:user-invalid) {
	border-color: crimson;
}

.field:has(input:user-invalid) .error-message {
	display: block;
}

Y deshabilita visualmente el botón de envío mientras haya campos obligatorios vacíos: 

	
form:has(:required:invalid) button[type="submit"] {
	opacity: 0.5;
	pointer-events: none;
}
2. Mostrar campos según una opción elegida

Sin una sola línea de JavaScript, un checkbox puede desplegar un bloque del formulario: 

	
<form class="checkout">
	<label>
		<input type="checkbox" id="factura">
		Necesito factura
	</label>
	<fieldset class="datos-fiscales">
		<!-- NIF, razón social... -->
	</fieldset>
</form>
	

	
.datos-fiscales {
	display: none;
}

.checkout:has(#factura:checked) .datos-fiscales {
	display: block;
}
3. Estados vacíos

Muestra un mensaje cuando una lista no tiene elementos: 

	
.empty-message {
	display: none;
}

.list-wrapper:not(:has(li)) .empty-message {
	display: block;
}
4. Layouts según la cantidad de hijos

Combinado con :nth-child(), :has() permite “contar” elementos y adaptar la rejilla: 

	
/* Tres columnas cuando hay 3 o más elementos */
.gallery:has(> :nth-child(3)) {
	grid-template-columns: repeat(3, 1fr);
}

/* Exactamente un elemento: ocupa todo el ancho */
.gallery:has(> :only-child) {
	grid-template-columns: 1fr;
}
5. Cambiar el tema desde cualquier punto de la página

Un interruptor colocado en cualquier sitio puede modificar variables en la raíz del documento:

	
:root:has(#modo-oscuro:checked) {
	--bg: #111;
	--text: #eee;
}

body {
	background: var(--bg, #fff);
	color: var(--text, #111);
}

El mismo truco sirve para bloquear el scroll cuando hay un modal abierto: 

	
body:has(dialog[open]) {
	overflow: hidden;
}
6. Resaltar el elemento activo y atenuar el resto
	
/* Atenúa todas las tarjetas cuando una tiene el cursor encima... */
.grid:has(.card:hover) .card:not(:hover) {
	opacity: 0.6;
	scale: 0.98;
}

Combinarlo con :not() e :is(), y la especificidad

La posición de :not() cambia por completo el significado. Conviene tenerlo claro porque es la confusión más habitual: 

	
/* Tarjetas que NO contienen ninguna imagen */
.card:not(:has(img)) {
	padding: 2rem;
}

/* Tarjetas que contienen algo que no es una imagen */
.card:has(:not(img)) {
	/* casi siempre coincide: cualquier otro hijo cumple */
}

:has() también se combina bien con :is() para agrupar condiciones sin repetir el selector exterior: 

	
.post:has(:is(h2, h3) + table) {
	max-width: 100%;
}

En cuanto a la especificidad, :has() se comporta como :is() y :not(): no suma nada por sí misma y toma la del selector más específico de su lista de argumentos. 

	
/* Especificidad (0, 2, 0): .card + .featured */
.card:has(.featured) { }

/* Especificidad (1, 1, 0): .card + #hero, aunque coincida por img */
.card:has(img, #hero) { }

Ese segundo caso sorprende a menudo: basta con que un ID aparezca en la lista para que todo el selector pese como si lo usara.

Soporte, rendimiento y limitaciones

:has() funciona en todos los navegadores modernos desde finales de 2023, cuando Firefox fue el último en incorporarlo. Para proyectos nuevos se puede usar sin miedo.

Navegador Versión con soporte Fecha aproximada
Firefox 121 diciembre de 2023
Chrome / Edge 105 agosto–septiembre de 2022
Safari (macOS e iOS) 15.4 marzo de 2022

Si aún tienes que dar soporte a navegadores antiguos, detecta la función con @supports selector() y deja un estilo por defecto razonable: 

	
/* Estilo base para todos */
.card {
	display: block;
}

/* Mejora progresiva */
@supports selector(:has(*)) {
	.card:has(img) {
		display: grid;
		grid-template-columns: 200px 1fr;
	}
}

Rendimiento. Los motores optimizan :has(), pero el coste crece con el alcance del selector. Algunas pautas:

  • Ancla el selector a un contenedor concreto (.card:has(img)) en lugar de a body o :root, salvo que realmente lo necesites.
  • Prefiere :has(> img) frente a :has(img) cuando sepas que el elemento es hijo directo: limita la búsqueda.
  • Evita :has() muy genéricos en páginas con miles de nodos que cambian a menudo, como tablas o listas virtualizadas.

Limitaciones que conviene conocer:

  • No se puede anidar: :has(:has(...)) no es válido.
  • No acepta pseudoelementos como argumento: :has(::before) no funciona.
  • La lista de argumentos no es tolerante a errores: si uno de los selectores es inválido, se descarta toda la regla.
  • No sustituye a la lógica de la aplicación: es perfecto para estilos que dependen del estado del DOM, no para gestionar datos.

Conclusión

:has() no es solo el selector padre que llevábamos años pidiendo: es una forma de que el CSS reaccione al contenido y al estado del documento. Formularios, estados vacíos, layouts que se adaptan al número de elementos o temas activados con un checkbox ya no necesitan JavaScript.

Empieza por un caso pequeño, como la tarjeta con imagen o el campo inválido, y verás cuántas clases auxiliares y scripts puedes borrar de tu proyecto.
