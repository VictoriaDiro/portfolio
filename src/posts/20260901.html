Markdown se ha convertido en un estándar de facto para la escritura en la web, utilizado en plataformas como GitHub, Reddit y Stack Overflow.

¿Qué es Markdown?

Markdown es un lenguaje de marcado ligero que permite dar formato a un texto usando solo caracteres normales del teclado. El texto se puede leer sin problema tal cual está escrito y, cuando se procesa, se convierte en HTML.

Lo creó John Gruber en 2004, con la colaboración de Aaron Swartz, con una idea muy clara: que un documento escrito en Markdown fuera legible incluso sin convertir, sin etiquetas que estorbaran la lectura. Hasta su nombre es un juego de palabras con markup, el término inglés para los lenguajes de marcado como HTML.

A día de hoy está presente en muchas de las herramientas que usamos cada día:

  • GitHub, donde los README.md son la portada de cada proyecto y se usa en issues, pull requests y comentarios.
  • Reddit y Stack Overflow, para escribir publicaciones y respuestas con código, listas y enlaces.
  • Discord, Slack y otras apps de mensajería, que aceptan parte de su sintaxis para dar formato a los mensajes.
  • Notion, Obsidian y otras apps de notas, que lo usan para escribir con atajos o directamente como formato de archivo.
  • Documentación y blogs, generados con herramientas como Astro, Hugo, Jekyll o Docusaurus a partir de archivos .md.
  • Asistentes de inteligencia artificial, que responden con Markdown para dar formato a sus respuestas y se configuran con archivos .md de instrucciones dentro de los proyectos.

¿Por qué usarlo?

  • Se aprende en minutos. Con media docena de símbolos cubres casi todo lo que necesitas.
  • Te deja centrarte en el contenido. Escribes sin levantar las manos del teclado ni pelearte con menús de formato.
  • Es texto plano. Se abre con cualquier editor, ocupa muy poco y funciona de maravilla con Git, que muestra los cambios línea a línea.
  • Es portable. El mismo archivo puede convertirse en una página web, un PDF o una presentación.
  • Admite HTML. Cuando la sintaxis se queda corta, puedes escribir HTML dentro del documento.

Sabores de Markdown

El Markdown original de Gruber dejaba muchos casos sin definir, así que cada plataforma acabó interpretándolo a su manera. Para poner orden nació CommonMark, una especificación que define con precisión la sintaxis básica. Sobre ella se construye GitHub Flavored Markdown (GFM), que añade tablas, listas de tareas, texto tachado y enlaces automáticos.

En esta guía repasamos toda la sintaxis con ejemplos: cada apartado incluye el código que debes escribir y una vista previa del resultado. Las secciones marcadas como extensión no forman parte del estándar y solo funcionan en las plataformas que las admiten, como GitHub.

Alertas (extensión de GitHub)

GitHub convierte en avisos destacados las citas que empiezan con un tipo de alerta entre corchetes. Hay cinco tipos: NOTE, TIP, IMPORTANT, WARNING y CAUTION.

	
		> [!NOTE]
		> Información útil que conviene tener en cuenta.

		> [!TIP]
		> Un consejo para hacer las cosas mejor o más fácilmente.

		> [!WARNING]
		> Algo que requiere atención para evitar problemas.

En plataformas que no admiten alertas, se muestran como una cita normal con el texto [!NOTE] al principio.

Los tres símbolos funcionan igual, pero cambiar de símbolo empieza una lista nueva. Elige uno y úsalo siempre; el guion es el más habitual.

Listas ordenadas

	
		1. Elemento de lista
		2. Elemento de lista
		3. Elemento de lista
  1. Elemento de lista
  2. Elemento de lista
  3. Elemento de lista

Solo importa el primer número, que marca dónde empieza la lista; el resto se numera solo. Puedes escribir 1. en todas las líneas y no tendrás que renumerar al añadir o quitar elementos.

Markdown no permite listas dentro de una celda, pero sí HTML. Ten en cuenta que algunas plataformas no aceptan HTML por seguridad y lo mostrarán como texto.

Bloque de código
	
		```css
		/* Esto es un comentario dentro de un bloque de código */
		.titulo {
			font-family: "Space Grotesk", sans-serif;
			color: rebeccapurple;
		}
	

		
			/* Esto es un comentario dentro de un bloque de código */
			.titulo {
				font-family: "Space Grotesk", sans-serif;

			}

Después de las comillas triples se indica el lenguaje (css, js, html, bash…) para que se resalte la sintaxis. Si quieres mostrar un bloque de código dentro de otro, rodea el exterior con cuatro comillas invertidas o con virgulillas (~~~).

Notas al pie (extensión)

	
		Markdown lo creó John Gruber en 2004.[^1]

		[^1]: Con la colaboración de Aaron Swartz.

Markdown lo creó John Gruber en 2004.1

  1. Con la colaboración de Aaron Swartz. ↩

Las notas se numeran solas y se colocan al final del documento, escribas donde escribas su contenido. Funcionan en GitHub, Obsidian y la mayoría de generadores de sitios.

Contenido desplegable

No tiene sintaxis propia en Markdown, pero como admite HTML, puedes usar las etiquetas <details> y <summary>:

	
		<details>
			<summary>Ver la solución</summary>
			La respuesta es **42**.
		</details>
Ver la solución

La respuesta es 42.

Deja una línea en blanco después de <summary> para que el Markdown de dentro se siga interpretando.

Diagramas con Mermaid (extensión)

GitHub, GitLab, Obsidian y muchos generadores de documentación dibujan diagramas a partir de bloques de código con el lenguaje mermaid:

	
		```mermaid
			flowchart LR
			A[Archivo .md] --> B[Procesador] --> C[Página HTML]
		```
Archivo .md → Procesador → Página HTML

Mermaid admite diagramas de flujo, de secuencia, de Gantt, de clases y más. Donde no está soportado, se muestra como un bloque de código normal.

Fórmulas matemáticas (extensión)

	
		La famosa ecuación de Einstein es $E = mc^2$.

		$$
		a^2 + b^2 = c^2
		$$

La famosa ecuación de Einstein es E = mc2.

a2 + b2 = c2

Entre $ la fórmula va dentro del texto; entre $$, en su propia línea. Usa la sintaxis de LaTeX y la admiten GitHub, Obsidian, Notion y Jupyter, entre otros.

Emojis (extensión)

	¡Publicado! :rocket: :tada:

¡Publicado! 🚀 🎉

Los códigos entre dos puntos funcionan en GitHub, Slack o Discord. En cualquier otro sitio, pega el emoji directamente: Markdown admite cualquier carácter Unicode.

Índice con anclas

Cada encabezado recibe automáticamente un identificador a partir de su texto, así que puedes enlazarlo con # para crear un índice clicable:

	
		- [Introducción](#introduccion)
			- [Instalación](#instalacion)
				- [Requisitos](#requisitos)

		## Introducción
			Este es un encabezado h2.
		### Instalación
			Este es un encabezado h3.
		#### Requisitos
			Este es un encabezado h4.
  • Introducción
    • Instalación
      • Requisitos

El identificador se genera en minúsculas, con los espacios convertidos en guiones y sin signos de puntuación. Cada plataforma trata las tildes a su manera: GitHub las mantiene (#introducción) y otras las eliminan, así que comprueba el resultado.

Metadatos (front matter)

Muchos generadores de blogs, como Astro, Hugo o Jekyll, y apps como Obsidian leen un bloque de datos al principio del archivo, escrito en YAML entre dos líneas de guiones:

	
		---
		title: Guía completa de Markdown
		date: 2025-10-01
		tags: [markdown, documentación, web]
		---

		# Guía completa de Markdown

Este bloque no se muestra en la página: lo usa la herramienta para generar el título, la fecha, las etiquetas o el listado de artículos.

Escapar caracteres

Para escribir un símbolo de Markdown sin que se aplique su formato, añade una barra invertida (\) delante:

	
		\*Esto no está en cursiva\*

		\# Esto no es un encabezado

*Esto no está en cursiva*

# Esto no es un encabezado
